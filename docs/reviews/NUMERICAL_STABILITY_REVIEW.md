# 二维求解器、工作流程与三维升级审查

审查日期：2026-10-12。范围为自有 C++/CUDA 求解器、采集流程和资源生命周期。结论来自代码检查及直接调用生产 CUDA 求解器的无窗口回归程序，不能代替完整地震数值方法的验收。

## 本轮确认并修复的问题

| 问题 | 原有影响 | 本轮处理 |
| --- | --- | --- |
| 标称八阶交错差分使用的四个权重不满足相应多项式矩条件 | 改变传播速度及高阶精度，不能按八阶误差估计 | 统一为 `1225/1024, -245/3072, 49/5120, -5/7168`，用 1/3/5/7 次多项式矩验证 |
| Type 3 垂向正应力导数的第三、第四组正向邻点少偏移一行 | 错误的高阶速度更新 | 改为 `i+3`、`i+4`，用三次应力场的解析速度增量验证 |
| Type 3 关闭 `upFlag` 仍执行自由表面更新和空气区清零 | 顶边无法恢复全域 PML 行为 | 关闭时复用 Type 1 的完整分裂场更新，逐点比较两方案结果 |
| Type 2 内部区仅在平均密度大于 1000 时更新 Vz，并把小于 1 的密度强制改为 1000 | 水体及更低密度材料出现非物理冻结或改变物性 | 移除两处密度阈值，保留正密度验证，用密度 1000、100、0.5 的解析算例验证 |
| CFL 上限写死为 0.601 | 与当前模板权重不一致，可能允许不稳定步长 | 二维等间距均匀介质上限按 `1/(sqrt(2)*sum(abs(weights)))` 计算，约 0.550；默认安全系数仍为 0.480 |
| Type 3 的 PML 厚度可以为 0，缺少顶部 ghost 行 | 应力模板可读到负行索引 | 初始化前检查几何，界面限制自由表面至少保留 4 行 |
| 网格先以 int 相乘，默认接收行在小网格中可能越界 | 分配尺寸溢出或非法接收点 | 先使用 size_t 检查乘积；明确限制当前二维 int 索引容量；默认接收行及通道数按尺寸生成 |
| CUDA 错误只打印后继续 | 分配或拷贝失败后仍计算错误结果 | 核心 CUDA 操作抛出明确异常，初始化失败清理本次资源，主入口统一捕获并退出 |
| 释放资源后不清空指针，清理依赖当前方案编号 | 重复释放、方案切换及部分初始化失败存在风险 | 按实际非空指针清理所有字段，最后重置整个 GPU 结构 |
| 接收点数、坐标、缓存容量不一致，空阵列未清理旧资源 | 采样读写越界或继续使用过期布局 | 原子替换接收缓冲区，检查坐标及容量，设备端再次检查展平索引 |
| 多点震源重叠时普通加法发生竞争，且没有遵守所选震源类型 | 丢失震源贡献，单点与多点模式语义不一致 | 共用注入实现，使用 atomicAdd，检查容量与注入位置 |
| 震源角度在 GPU 结构中存为 int | 小数角度被截断 | 改为 float |
| 采样步取整后 SEG-Y 仍按请求采样率写入 dt | 数据与时间轴不一致，频率及走时解释可能错误 | 记录实际 `stride * dt`，按实际间隔分配缓冲并导出；录制中改变 dt 会明确拒绝继续采集 |
| 每个采样点创建两个 host vector | 不必要的堆分配 | 重用采样暂存数组；同步 D2H 拷贝仍待后续批量化 |
| 回放帧尺寸未与当前 GPU 网格比较 | 向 GPU 拷贝超过帧数组长度 | 上传前检查帧大小 |
| 启动时为遗留生命游戏分配随机状态及缓冲 | 首页无意义的额外显存和初始化开销 | 改为进入该演示页面时才分配，并补充退出清理 |
| 地震纹理、互操作资源、显示缓冲及模型纹理退出时遗漏释放 | 生命周期不完整 | 统一加入正常与异常退出清理；显示映射增加作用域清理 |
| ImPlot 上下文创建两次、着色器链接无检查 | 上下文泄漏或使用无效渲染管线 | 保留一次上下文创建，共用带编译/链接检查的着色器创建函数 |

这些修复会改变旧版本的数值输出，尤其是差分权重和 Type 2 密度阈值。旧二进制回放仍可按原帧显示，但重新计算的波形不能假定与旧结果逐点一致。

## 当前边界条件的可信范围

- Type 1 是全域分裂场 PML；Type 2 在内部使用总场、在 PML 中使用分裂场。现有实现没有 CPML 的卷积记忆变量，应避免将其称为 CPML。
- 四周不更新的模板保护带及零值边缘是计算闭合处理，PML 的作用是在波到达该闭合带前衰减；npml=0 的边缘属于人工反射边界，不能解释为所有分量都满足物理自由面。
- Type 3 是固定水平行的平面自由表面。法向应力在表面为零，正应力按整点、剪切应力按交错半点作反对称镜像。已有检查覆盖法向应力及其 ghost 奇对称关系。
- 表面附近的剪应力更新仍只有前两组导数项，且依赖空气侧速度处理。这不能沿用内部八阶精度的结论；还需完整的离散表面闭合推导和解析/可信参考解验证，当前不声称自由表面已全面正确。
- 顶面与侧 PML 交界、交错半网格阻尼的左右对应、斜入射及掠入射反射都需要独立算例。现有均匀算例只验证有限时窗内的吸收改善，不能推出全部频率/入射角的反射上界。
- 场景中的起伏地形由材料分布表示，没有独立的逐列自由表面 mask。它不能作为已经实现任意地形牵引自由边界的证据。
- 流固界面的剪切模量平均及 PML 内将流体“固化”的既有策略会改变物理模型。三维升级前应以流体/固体反射透射系数及能量守恒算例决定处理方法。

## 已执行的验证及其限制

在 RTX 4060 Laptop GPU 上构建 Debug 版本，启用 `SEISSIM_BUILD_SOLVER_TESTS`，通过 `SolverRegression` 执行以下检查：

1. 八阶导数的四个多项式矩、网格乘积溢出、过薄/过厚边界、采样步对齐和非法采样参数。
2. 三种方案的解析三次应力梯度，包含 Type 2 的低密度材料。
3. 自由表面的法向应力为零和四层正应力反对称镜像；关闭自由表面后与 Type 1 逐点相同。
4. 200 个重叠震源的累加；接收点更新失败保持旧资源、空接收集清理、非法设备端接收索引保护、回放尺寸检查及重复释放。
5. 非物理密度、非正体积模量及过大时间步的拒绝。
6. 三种方案的有限时间步推进，接收记录与最终 Vz 场均保持有限值。
7. 96×96 网格与 288×288 大域参考比较，700 个时间步、同一震源和相对位置接收点。Type 1/2 的晚到窗口误差范数与无阻尼反射对照之比分别约为 0.0433824、0.0433818。

第 7 项测量的是某一接收记录时间窗的误差范数比，**不是通用 PML 反射系数，也不是整个波场的误差界**。测试直接调用生产 CUDA 更新和采样函数，不覆盖所有 GUI 事件、导入模型、导出格式或真实显存耗尽的路径。GPU 检查不可执行时测试返回“跳过”，不会算作通过。

CUDA Compute Sanitizer memcheck 对这些算例报告 0 个内存错误。图形界面交互、CUDA/OpenGL 跨设备组合和长期运行还需另行验证。

## 三维升级前仍需优先解决

| 优先级 | 工作 | 原因 |
| --- | --- | --- |
| 高 | 用 Rayleigh 波、自由面 P/S 反射、流固界面及斜入射 PML 算例建立数值基准 | 避免把二维边界误差复制到三维 |
| 高 | 将求解状态、材料、震源、接收点及时间轴移入 SimulationSession | 目前 ctx/par/gpu_data/rec 与 ImGui 全局状态耦合，缺少统一的操作事务 |
| 高 | 将每炮几何与采样元数据冻结为记录快照 | 当前导出仍读取编辑中的震源位置；录制中改通道、位置、模型可能破坏记录语义 |
| 高 | 重构 SEG-Y 错误返回、数组长度检查、样本数/时间间隔字段范围及写入失败检测 | 当前导出会把字段强制缩为 16 位，写入失败也可能显示成功；10 Hz 等低采样率无法直接塞入现有微秒字段 |
| 高 | 明确三维观测几何的 X/Y/Z、深度和高程语义 | 当前二维深度借用 Y 字段，不可直接沿用为三维水平 Y 坐标 |
| 中 | 将同步逐步接收拷贝改为批量或 pinned ring buffer | 采样数增加后 PCIe 同步会占用主线程 |
| 中 | 将回放改为显存/内存预算约束下的分块落盘 | 三维整场按帧常驻 CPU 内存不可持续 |
| 中 | 分拆大型头文件、移除未使用字段/演示路径并统一命名 | 确定核心 API 后再迁移 UI，减小编译和维护成本 |
| 中 | 将预期的用户配置错误呈现在界面，保留 fail-fast 用于无法恢复的设备错误 | 本轮入口异常处理会明确诊断并退出，尚未实现完整的工作区恢复 |

## 推荐的三维实施顺序

1. 固定二维回归基线，将网格几何、材料、边界和采集配置从 UI 中抽离，并让当前二维后端继续通过同一组数值检查。
2. 新建 `GridGeometry3D`，使用检查溢出的 size_t 乘积与显式 x/y/z stride；提供独立的 dx/dy/dz。当前二维内核仍明确限制 int 索引，不将结构改名当作三维支持。
3. 建立显存预算，再实现三个速度分量与六个独立应力分量；PML 辅助量和边界闭合按三维重新推导。CFL 按三个方向的间距重新计算，不能复制二维 0.480 系数。
4. 先实现均匀弹性介质、受控点源和三分量接收，再实现六面吸收边界、平面自由表面和异质介质。
5. 以切片显示和按需快照替代每帧完整三维数据拷贝，随后再考虑体绘制、流固耦合、复杂地形与多 GPU。

仅九个单精度物理场，512³ 网格已需 4.5 GiB；材料、PML 辅助量、显示、采集和驱动开销另计。因此 8 GiB 显卡上的三维规模必须根据实际算法预算确定，不能只按物理场数量估算。
